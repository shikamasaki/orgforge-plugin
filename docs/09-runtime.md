# 09 — The Runtime: Where the Guarantees Are Actually Enforced

> The chart (organization.yaml), the charter (constitution.yaml), the moves, the sensors,
> and the ledger schema are all *data*. Something must execute them and refuse what they
> forbid. This document specifies that runtime: its enforcement points, its clocks, its
> failure behavior. It is a spec, not code — but every rule here is stated as a check an
> implementation either performs or provably lacks, so "implemented" is a testable claim.
> The lint (tools/org_lint.py) verifies the *data* is coherent; the runtime enforces it
> *at execution time*. Both are needed; neither substitutes for the other.

---

## 1. The mediation principle

**Every agent action passes through the runtime; no agent holds a raw capability.**
Agents don't open files, call APIs, or write the ledger directly — they request actions
from the runtime, which knows the actor's identity (from the session, never from the
request payload) and mediates. This single choke point is what makes the rest
enforceable; an implementation that gives any agent an unmediated side channel has not
implemented this spec, whatever else it does.

## 2. Tier enforcement (closing the self-classification hole)

The adversarial review's top finding was that tier membership was self-declared. The
runtime closes it:

1. Every requested action carries a machine-readable **effect descriptor** (what it
   writes, what leaves the boundary, what assets it touches) — generated by the runtime
   from the action's actual parameters, not asserted by the agent.
2. A **classification table** compiled from the constitution (`irreversible.held_actions`,
   `charter.items`, delegated bounds) maps effect descriptors to tiers. The table is
   data; the classifier is mechanistic and its decisions are ledgered.
3. **Unclassifiable actions default to irreversible-hold.** Fail-safe: an effect the
   table doesn't recognize is treated as the most restricted class until a human extends
   the table (a charter change). The org cannot invent a new kind of action into Tier 1.
4. Tier behavior then follows docs/06 §2.1: delegated executes, charter files a
   proposal, irreversible stages up to the staging guards.

## 3. Clocks, cadences, and the event bus

**The ledger is the event bus.** Appends are the only publications; consumers tail the
sequence. Delivery is at-least-once; consumers dedup on event `id` (idempotency is the
consumer's contract).

**Cadence grammar** (lint-checked): `every_<int>_<min|hours>` for timers;
`on_<trigger>` where `<trigger>` is a key of `ledger-schema.yaml: triggers`;
`on_operator_instruction` for human-driven roles. Timers are durable: they are derived
from the last `cycle_started` in the ledger, so a crash-restart resumes the schedule
from the record, not from memory (Organ 4's durability, made concrete).

**A cycle** is: registrar assembles the pack (ledger-schema `context_pack.algorithm`) →
`cycle_started` → the role works through mediated actions → `cycle_completed` with token
accounting and views_referenced (the raw material for the budget guard and the
context_utilization sensor). A cycle that crashes resumes idempotently from its manifest
or is abandoned with an anomaly event — never silently retried into duplicate effects.

## 4. Budget guard and no-progress

Token counters aggregate `cycle_completed.tokens` per role and per category against the
constitution's window caps. At cap: the role's timer is paused until the window rolls,
and the pause is ledgered. The **no-progress rule** is evaluated by the registrar over
`move_executed` + `sensor_reading` history: same signal, same move, N times, no
improvement in the signal → that line suspends and ONE proposal is filed (dedup_key
guarantees one).

## 5. Halt, watchdog, and the two pages

- **Global halt flag**: held outside the org's write authority (repo/infra level, with
  the constitution). The runtime checks it before every mediated action; tripping it
  ledgers `halt_tripped` and freezes all timers. Humans set it; the watchdog may set it;
  agents may *request* it (that request is always honored — halting is the one action an
  agent may always take).
- **The watchdog** is an external process, not an org member: it replays the ledger's
  hash chain, verifies the invariants, and emits `heartbeat`. A missing heartbeat, a
  broken chain, or a tripped safety limit fires the **wake-up push** — the only page.
  Everything else waits for the digest. The watchdog's independence is what makes
  "the org self-reports its own corruption" no longer true (docs/06 §2.4).
- **Night safe mode** is a runtime mode, entered on schedule or on any
  `anomaly_detected` with `matched_pattern: none`: admission requests are answered
  `park` (docs/06 §2.4), exploration actions proceed, and exit requires either a
  matched pre-registered pattern (sensors.yaml `preregistered_for_night`) or a human.

## 6. Determinism obligations

Two artifacts must be **reproducible projections**: the morning digest (same window +
same ledger ⇒ byte-identical output; any human can re-run it) and the succession
package (docs/06 §4.2). Implementations must expose the projection as a pure function
over the ledger — that property, not trust in the registrar, is what makes the digest
audit-proof. The registrar *schedules* projections; it cannot *shape* them.

## 7. Identity and the constitution's own protection

`no_agent_writes_this_file` is enforced in two layers: the runtime refuses mediated
writes to the constitution path from any agent actor, and the repository refuses
commits touching it from agent identities (branch protection / CI authorship check —
CODEOWNERS-style, with the humans as owners). The lint's CH check only verifies the
declaration; these two enforcement layers are what make it true.

## 8. Conformance checklist (what "implemented" means)

An implementation of this repo may claim conformance when it can demonstrate, with
ledger evidence:

- [ ] no agent action bypasses mediation (§1) — probe: an agent attempting a direct
      write produces a denial event, not an effect
- [ ] an unclassifiable action lands in irreversible-hold (§2.3)
- [ ] a crash mid-cycle resumes or abandons with an anomaly — never double-executes (§3)
- [ ] a window cap pauses the role and ledgers the pause (§4)
- [ ] a broken hash chain pages within one heartbeat interval (§5)
- [ ] the digest re-run by a human is byte-identical (§6)
- [ ] an agent-authored constitution diff is refused at both layers (§7)
- [ ] every sensor_reading a move cites exists in the ledger before the move_executed
      event (moves.yaml header rule)

*Status: this is a specification with testable conformance, not shipped code. It is the
newest layer of the repo; treat unimplemented conformance items as the honest boundary
of what the system currently guarantees.*
