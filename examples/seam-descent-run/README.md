# Seam-descent run — the org self-drives scoped brains + seam contracts, end to end

This is the end-to-end verification (on the real Claude Code CLI) that the delegation model
holds when **nothing is scripted by hand**: a top manager, given only a build request and a
profile stating the delegation *discipline*, decides on its own how to split, and for each
child it renders a **hand-off packet** — a fixed **seam contract** plus **doctrine scoped to
that child** — using `tools/handoff.py`. The child integrates back to the contract exactly.

It closes the loop on two things at once: the previously-unverified claim that multi-level
brain-descent runs *from the profile alone*, and the design fix from the three-perspective
review (fix the seam, not a global axis).

## What was given

- [`REQUEST.txt`](REQUEST.txt): build a task-tracker as three files that MUST integrate
  (`store.js` / `api.js` / `cli.js`) agreeing on a task shape `{id,text,done}`. WHAT only.
- [`manager-profile.md`](manager-profile.md): one profile for every layer. It states the
  delegation *duty* — "if you split, build each child's hand-off with `handoff.py` (slice +
  seam contract + scoped brain), then spawn." It prescribes **no** depth, **no** axis, **no**
  piece count. Those are the org's judgment.

## What the org did, unprompted (verified)

From [`process-log.md`](process-log.md) and the transcripts:

1. The ROOT manager decided `SUBDIVIDE: 3 independent slices (store/api/cli), one shared seam
   {id,text,done}` and chose its own split axis (`layer boundary`). I did not specify this.
2. It ran `handoff.py` itself (5 Bash calls) and emitted three packets —
   [`handoff-store-worker.md`](handoff-store-worker.md),
   [`handoff-api-worker.md`](handoff-api-worker.md),
   [`handoff-cli-worker.md`](handoff-cli-worker.md) — then Agent-spawned three children
   (3 real subagent transcripts).
3. Each child judged its slice a single leaf and **built it directly** (correct granularity —
   no over-splitting), integrated to its contract, and reported up. The ROOT reviewed against
   the seam, integrated, and verified by running it.

## The properties that held (physical evidence)

- **Self-driven, from the profile alone.** The hand-off packets were generated by the org via
  the tool, not authored by me. Multi-role brain-descent needs only the profile discipline.
- **Seam fixed, not axis.** Each packet carries `inputs` / `outputs` (the exact interface) as a
  hard constraint plus the `{id,text,done}` invariant; the axis is present only as local advice
  ("your call, do not inherit a global one").
- **Brain scoped, no leak.** The store packet carries only the store-layer doctrine; the API
  "pure dispatch" rule and the CLI "argv/stdout" rule do **not** appear in it, and vice-versa.
- **Doctrine changed behavior, not just decoration.** The store-worker's rule ("a data layer
  owns persistence only; never parse argv or format output") shows up in the code: `store.js`
  contains **no** `process.argv` and **no** `console.log`; only `cli.js` touches argv.
- **Integration did not drift.** Running the delivered files from a clean state (my own check,
  not the org's report): `add` → `list` → `toggle` → `remove` and persistence across separate
  `node` processes all work; all three files agree on `{id,text,done}`.

## Honest limits

- The tree went two levels (root → three leaf workers). A leaf here correctly chose not to
  split, so a spawned child that *itself* emits a further seam contract to grandchildren has
  been shown by the two-level `handoff` artifacts in `../doctrine-scoping/`, but not by a
  single autonomous run reaching depth 3. A task heavy enough to force depth-3 from judgment
  alone is the remaining thing to exercise.
- The doctrine root path is wired into the profile as `<DOCTRINE_ROOT>` here (sanitized); a
  real deployment sets it per the runner's `--doctrine`.
